SensePlay Analytics Engine

ai × data × edtech

Educational games produce a constant stream of raw gameplay events. This engine turns that stream into useful insight: session metrics, progress measures, and AI-assisted narrative reports that educators can actually read.

APPROACH FastAPI ingests gameplay events; PostgreSQL stores them with pgvector for semantic search over session patterns; Celery and Redis run asynchronous report jobs; Groq drafts AI-assisted narratives. Alembic manages the schema, and the repo ships tests and project documentation.

  • Python
  • FastAPI
  • PostgreSQL
  • pgvector
  • Celery
  • Redis
  • Groq
  • Alembic

TOIO Games

stem games × platform

An education and STEM-games codebase organised as a platform, not a single app. Interactive learning games backed by a web frontend, analytics, a server, and custom hardware for accessible physical input.

APPROACH Five areas under one roof: Unity WebGL games covering memory, sequence, pattern, code-lock and tug-of-war challenges; a React web layer; an analytics engine; a Node.js server; and a hardware module that includes the MekiMeki PCB, exploring accessible controllers for hands-on play.

how I build

  1. Start with the user and environment. Good solutions account for accessibility, connectivity, available devices, language, and context.
  2. Treat accessibility as a design constraint from day one. Input options and clear feedback early, not tacked on at the end.
  3. Connect design to engineering. Interaction details, loading states, error handling, and maintainable architecture all matter.
  4. Use AI with a purpose. Useful analysis and assistance, with clear limits and human judgement in the loop.
  5. Build, test, learn, improve. Practical prototypes, real feedback, and steadily hardening the parts that prove useful.
